# PR×PR — 열린 PR 간 의미 충돌 탐지기

> 각자 보면 무결한데 **합쳐지면 서로의 전제를 깨뜨리는** PR 쌍을, 병합 전에 찾아 근거·확인 지점과 함께 제시한다.

**상태**: Step 0 ✅ 구현 완료 · Step 1–2 설계 확정 · Step 3 설계 진행 · 시각화 목업 완료

---

## 배경 — 아무도 검사하지 않는 축

기존 CI·머지 검사는 전부 **`PR ↔ main`** 축만 본다. 각 PR이 개별 CI를 통과하고 git 텍스트 충돌이 없으면 병합 가능으로 처리된다. 그러나 두 PR이 **각자는 무결한데 병합된 상태에서만** 로직이 깨지는 **semantic merge conflict**는 이 검사망을 그대로 통과한다 — 결함이 어느 한쪽 PR이 아니라 **조합에만** 존재하기 때문이다.

AI 코딩 에이전트의 PR 대량 생산으로 이 사각지대는 빠르게 커지고 있다. 대형 오픈소스의 열린 PR은 이미 수천 개 단위다 (`openclaw/openclaw` **2,813개**, 2026-07 실측).

**실증 사례** — `#101471`(엔진이 compaction 소유 시 overflow 감시 스킵) × `#95272`(에이전트 self-compaction 추가):
두 PR 모두 모범적 테스트를 갖췄으나 **테스트 환경이 서로소**였다. "엔진 있음 + 버튼 있음" 조합은 어느 쪽도 검증하지 않아, 병합 시 overflow 감시 공백이 발생한다.
→ 정밀 분석: [`증거자료_충돌사례_101471x95272.md`](증거자료_충돌사례_101471x95272.md)

## 접근 — LLM 샌드위치

의미 이해는 정확하지만 비싸고, 조합 수는 제곱으로 폭발한다(2,813개 → 수백만 쌍). 그래서 **비싼 LLM 판단을 파이프라인 양 끝에 얇게 배치하고, 폭발 구간은 결정적 규칙으로 커팅**한다.

- LLM 호출을 **PR당 1회**(Step 1) + **쌍당 1회**(Step 3)로 상한.
- 그 사이 조합 폭발 구간(Step 2)은 **LLM 없이** 결정적 신호로 후보를 상위 K쌍까지 압축.

```
열린 PR                                        2,813
  │
  │  Step 0 · 룰 기반 필터  (LLM 없음)
  │          문서 · 테스트 · 의존성 PR 제외
  ▼                                            2,310
  │  Step 1 · Intent Card 추출  (LLM · PR당 1회)
  │          의도 · 행동변화 · 공유자원 · 가정
  ▼                                            카드 N장
  │  Step 2 · 버킷팅 & 프루닝  (LLM 없음)
  │          자원 역색인 + 임베딩 유사 + 이슈참조
  ▼                                            후보 ~50쌍
  │  Step 3 · 관계 판정  (IBM Bob / Opus 4.8 · 쌍당 1회)
  │          유형 · 심각도 · 신뢰도 · 근거 · 확인방법
  ▼
  시각화 · PR 관계 그래프
```

## 단계별 설계

각 단계를 **원칙 → 방법 → 품질 측정**으로 정리한다.

### Step 0 · 룰 기반 필터
- **원칙** — 배제는 100% 확실할 때만. 애매하면 통과(놓치는 비용이 헛후보 비용보다 크다).
- **방법** — 파일 경로 glob으로 `docs/test/deps/config/assets/logic` 분류 → **logic 파일이 하나라도 있으면 통과**. 모든 판정에 `reason` 기록(감사 가능). git 충돌 PR은 폐기하지 않고 **deferred**(리베이스 후 복귀). 의존성 봇만 작성자 기준 제외 — **AI 에이전트 PR은 표적 모집단이므로 통과**시킨다.
- **품질** — openclaw 2,813개 실측 통과율 **82.1%**.

### Step 1 · Intent Card 추출 (LLM)
- **원칙** — 기계가 조인하는 곳만 구조화하고, 판단 재료는 문장으로 남긴다.
- **카드 스키마**
  - `summary`
  - `behavior_changes` — `surface` / `before` / `after`
  - `touched_resources` — 접두어로 **충돌 전파 통로의 종류**를 표기 (아래 표)
  - `assumptions` — 이 PR이 계속 참이라 기대하는 것 (Step 3 판정의 재료)
  - `confidence`
- **일관성** — 스키마와 추출 프롬프트를 **단일 파일**에서만 관리 → 추출자 간 형식 불일치 차단.

| `touched_resources` 접두어 | 의미 |
|---|---|
| `state:` | 공유 런타임 상태 (메모리·캐시·세션) |
| `config:` | 실행 전 결정되는 설정·플래그·env |
| `api:` | 공개 인터페이스 (HTTP 엔드포인트·함수 시그니처·CLI) |
| `schema:` | 데이터 구조 (DB 테이블·struct·JSON 스펙) |
| `event:` | 발행/구독 이벤트 타입·payload |
| `file:` | 다른 코드가 포맷·경로를 계약처럼 의존하는 파일 |

### Step 2 · 버킷팅 & 프루닝 (LLM 없음)
- **원칙** — 조합 폭발을 결정적 신호로 커팅하되, 임계값이 아니라 **예산(상위 K=50)** 으로 자른다.
- **후보 점수 = 4개 신호 합산**
  1. 자원 **정확** 일치 (강 · 인기 자원은 IDF 삭감)
  2. 자원 **유사** 일치 (중)
  3. 문장 **임베딩** 유사 (중 · 이름 흔들림·누락 안전망, 쌍별 LLM 호출 없이 확장)
  4. 도메인 ∩ 파일 겹침 (약)
- **폭발 방지** — 대형 버킷(>15 PR)은 쌍 생성 스킵(제곱 폭발 차단).
- **품질** — 시드 회귀 세트(확인된 진짜 쌍의 생존 검사) + 기각 쌍 샘플 재판정으로 false negative 추적.
- 설계 문서: [`설계_Step2_버킷팅프루닝.md`](설계_Step2_버킷팅프루닝.md)

### Step 3 · 관계 판정 (IBM Bob / Opus 4.8)
- **원칙** — "충돌인가?"를 먼저 묻지 않는다(yes-bias 방지). **열고 나서 조인다.**
- **절차**
  1. 병합 상태의 상호작용을 자유 기술
  2. 공유 자원의 **소유권·수명 규칙 대조** + 가정 상호 검증(의무 체크)
  3. 관계 유형 분류 (아래 표)
  4. 충돌이면 — 심각도 · 신뢰도 · **근거 인용** · **확인 방법**(사람이 볼 코드 지점). *확인 방법 없는 충돌 판정은 무효.*
- **정직한 불확실성** — 판정 불가 시 `uncertain`(그래프의 노란 엣지 · Bob 코드 검사 대기열).
- **승격** — Bob이 레포 코드를 직접 열어 `uncertain`을 확정 판정으로 승격 → 세션 리포트 export가 제출물.
- **품질** — 양성/음성 대조군 + 재현성 테스트.

| 관계 유형 | 의미 |
|---|---|
| `semantic_conflict` | 조합에서만 계약이 깨짐 (표적) |
| `duplicate` | 같은 문제를 중복 해결 |
| `supersedes` | 한쪽이 다른 쪽을 대체 |
| `depends_on` | 한쪽이 다른 쪽 선행을 요구 |
| `complements` | 함께 작동하도록 의도된 확장 |
| `unrelated` | 인과 상호작용 없음 |

### 시각화
후보 쌍에 걸린 PR만 렌더(~70 노드)하는 PR 관계 그래프.
- **노드** = PR, **엣지** = 관계 — 🔴 충돌 · 🟡 불확실 · 🟣 중복 · ⚪ 무해
- 엣지 클릭 → 두 Intent Card를 나란히, **충돌하는 가정을 마주 보게** 배치, 확인 체크리스트 제공
- 데이터 계약 = Step 2/3 출력 JSONL 그대로.
